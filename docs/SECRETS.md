# مدیریت رازها (بخش ۲-ب۱)

این سند می‌گوید چه چیزهایی «راز» هستند، چطور از لورفتنشان جلوگیری می‌شود، و **اگر لو رفتند دقیقاً چه کنیم.**

## ۱. چه چیزهایی راز است

| راز | کجاست | اگر لو برود |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `.env` | هر کسی می‌تواند به‌جای بات پیام بفرستد/بخواند و (با polling) دیگر نمی‌توانید بات را اجرا کنید |
| `ADMIN_SESSION_SECRET` | `.env` | هر کسی می‌تواند کوکی نشست جعلی بسازد و **ادمین پنل** شود |
| کلید خصوصی TLS (`*-key.pem`) | `.ssl/` | امکان جعل سرور و شنود ترافیک؛ باید گواهی ابطال و دوباره صادر شود |
| فایل دیتابیس و بک‌آپ‌ها | `data/` | داده‌ی شخصی کارمندان (نام، آیدی تلگرام، ساعات تردد، مرخصی) |

ریشه‌ی همه‌ی اقدامات پایین: **تعویض مقدار، نه فقط پنهان‌کردن.** رازی که لو رفته را فقط با ساختن مقدار جدید می‌شود امن کرد.

## ۲. جلوگیری از لورفتن (آنچه در کد پیاده شده)

### ۲.۱ بسته‌ی تحویل/استقرار بدون راز
```bash
npm run package                       # → dist/farazhonar-attendance-<نسخه>-<تاریخ>.zip
node scripts/package-release.js --out C:\temp\release.zip
```
- **همیشه حذف می‌شوند:** `.env` و هر `.env.*` (به‌جز `.env.example`)، `.ssl/`، `data/` (دیتابیس و بک‌آپ)، `node_modules/`، `.git/`، `logs/` و `*.log`، `*.pem` `*.key` `*.pfx` `*.p12` `*.crt` `*.cer`، `*.db` `*.sqlite*`، و zipهای قبلی.
- **دو بررسی روی خودِ zip ساخته‌شده** (نه فقط روی فهرست ورودی): (۱) فهرست ممنوعه‌ها، (۲) اسکن رازها روی محتوای فایل‌های متنی. اگر هرکدام چیزی پیدا کند، **فایل خروجی ساخته نمی‌شود** و برنامه با کد ۱ خارج می‌شود (fail-closed).
- بدون وابستگی npm؛ zip با `zlib` داخلی Node ساخته می‌شود و روی ویندوز هم کار می‌کند.
- ⚠️ هر وقت پروژه را برای کسی می‌فرستید (توسعه‌دهنده، ابزار هوش مصنوعی، پشتیبان) فقط خروجی `npm run package` را بفرستید، نه zip کردن دستی پوشه.

### ۲.۲ اسکن رازها
```bash
npm run secret-scan          # کد خروج ۰ = تمیز، ۱ = یافته دارد
node scripts/secret-scan.js --json
```
پیدا می‌کند: توکن بات تلگرام (حتی داخل URL مثل `api.telegram.org/bot<TOKEN>/…`)، بلوک PEM کلید خصوصی، فایل‌های `*.pem/*.key/*.pfx` سرگردان، و انتساب مشکوک به نام‌هایی مثل `SECRET`/`TOKEN`/`PASSWORD`/`API_KEY` با مقدار تصادفی‌نما. مقدار راز هرگز چاپ نمی‌شود (فقط نوع، فایل، شماره خط و پیش‌نمایش ماسک‌شده).
- اسکن نمی‌شوند: `.env` ریشه، `.ssl/`، `data/`، `node_modules/`، `.git/` (این‌ها راز محلی‌اند؛ جلوی رفتنشان به بیرون را `package-release` و `.gitignore` می‌گیرند). هر `.env.*` دیگر (مثل `.env.production`) اسکن می‌شود.
- مثبت کاذب عمدی (مثلاً توکن ساختگی تست): در **همان خط** کامنت `// secret-scan:allow` بگذارید.
- خودِ `npm test` هم بررسی می‌کند که پروژه تمیز بماند.
- پیشنهاد: قبل از هر `git commit` یا ارسال بسته یک‌بار `npm run secret-scan` بزنید (خودکارسازی با git hook عمداً اضافه نشد چون hookها روی کلون‌ها نمی‌مانند).

### ۲.۳ کنترل هنگام بالا آمدن
در `src/utils/startupChecks.js`:
- **production:** اگر `ADMIN_SESSION_SECRET` خالی، کوتاه‌تر از **۳۲ نویسه**، شبیه مقدار نمونه (`change-me`، `example`، `dev-only` و …) یا غیرتصادفی (کمتر از ۸ نویسه‌ی متفاوت) باشد، **سرور بالا نمی‌آید** و حتی به دیتابیس هم دست نمی‌زند (نه migration، نه بک‌آپ).
- **همه‌ی محیط‌ها:** `TELEGRAM_BOT_USERNAME` خالی ← هشدار واضح در لاگ (دکمه‌ی «ورود با تلگرام» کار نمی‌کند).
- در محیط توسعه، راز ضعیف فقط هشدار است.
- ساخت مقدار مناسب:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```

### ۲.۴ `.gitignore`
`.env`، `.env.*` (به‌جز `.env.example`)، `.ssl/`، `data/*.db*`، `data/backups/`، `data/attachments/`، `*.pem` `*.key` `*.pfx` `*.p12`، `*.log`، `logs/`، `dist/`. بررسی‌شده با `git check-ignore`.

## ۳. دسترسی فایل‌ها روی ویندوز (icacls)

هدف: `.env` و `.ssl\` فقط برای **حساب اجرای سرویس NSSM** و ادمین‌ها خواندنی باشند، نه همه‌ی کاربران سیستم.

۱) ببینید سرویس با کدام حساب اجرا می‌شود (نام سرویس پیش‌فرض: `FarazHonarAttendance`):
```powershell
nssm get FarazHonarAttendance ObjectName
```
اگر مقدار `LocalSystem` بود (پیش‌فرض NSSM)، حساب `NT AUTHORITY\SYSTEM` است.

۲) ارث‌بری را قطع و فقط حساب‌های لازم را مجاز کنید (از PowerShell با دسترسی Administrator، در ریشه‌ی پروژه):
```powershell
# فایل .env — فقط خواندن برای حساب سرویس، کنترل کامل برای Administrators
icacls ".env" /inheritance:r /grant:r "NT AUTHORITY\SYSTEM:(R)" "BUILTIN\Administrators:(F)"

# پوشه‌ی .ssl (شامل کلید خصوصی)
icacls ".ssl" /inheritance:r /grant:r "NT AUTHORITY\SYSTEM:(OI)(CI)(R)" "BUILTIN\Administrators:(OI)(CI)(F)"

# پوشه‌ی data (دیتابیس و بک‌آپ) — سرویس باید بتواند بنویسد
icacls "data" /inheritance:r /grant:r "NT AUTHORITY\SYSTEM:(OI)(CI)(M)" "BUILTIN\Administrators:(OI)(CI)(F)"
```
اگر سرویس با حساب دیگری اجرا می‌شود (مثلاً `.\svc-attendance`)، به‌جای `NT AUTHORITY\SYSTEM` آن را بنویسید.

۳) بررسی:
```powershell
icacls ".env"
icacls ".ssl"
```
۴) سرویس را restart کنید و تأیید کنید بالا آمده: `nssm restart FarazHonarAttendance`.

> ⚠️ این دستورات روی ویندوز واقعی توسط من اجرا نشده‌اند؛ اول روی یک کپی/`.env` آزمایشی امتحان کنید. اگر `win-acme` با حساب دیگری گواهی را در `.ssl\` می‌نویسد، همان حساب هم باید دسترسی نوشتن داشته باشد.

## ۴. اگر راز لو رفت — چک‌لیست

ترتیب مهم است: اول **ابطال**، بعد **جایگزینی**، بعد **بررسی سوءاستفاده**.

### الف) توکن بات تلگرام
1. در تلگرام به `@BotFather` بروید ← `/mybots` ← بات را انتخاب کنید ← **API Token** ← **Revoke current token** (یا دستور `/revoke`). توکن قدیمی همان لحظه باطل می‌شود.
2. توکن جدید را در `.env` به‌جای `TELEGRAM_BOT_TOKEN` بگذارید.
3. `nssm restart FarazHonarAttendance`. (تا restart، بات قطع است.)
4. تأیید: `/start` را به بات بزنید و در لاگ سرویس پیام «بات تلگرام در حالت polling راه‌اندازی شد» را ببینید.
5. دامنه‌ی Login Widget (`/setdomain`) و دکمه‌ی منو با تغییر توکن عوض نمی‌شوند.
6. اگر دیدید پیام‌های ناشناس به نام بات رفته، تاریخچه‌ی چت‌ها را بررسی و به کاربران اطلاع دهید.

### ب) `ADMIN_SESSION_SECRET`
1. مقدار جدید بسازید (`randomBytes(32).toString('hex')`) و در `.env` بگذارید.
2. `nssm restart FarazHonarAttendance`.
3. **همه‌ی نشست‌های پنل بلافاصله باطل می‌شوند** و همه باید دوباره وارد شوند (از `/panel` در بات). این تنها راه امن در برابر کسی است که خودِ راز را دارد.
4. در پنل ← audit را برای تغییرات مشکوک (کاربر/نقش/تنظیمات/رکورد تردد) در بازه‌ی احتمالی افشا بررسی کنید.
5. جزئیات ابطال نشست‌ها: [`SECURITY.md`](SECURITY.md) بخش ۴.

### ج) کلید خصوصی TLS
1. گواهی قدیمی را نزد CA **ابطال** کنید (برای Let's Encrypt با `win-acme`/`wacs.exe` یا ابزار ACME مربوطه، revoke).
2. گواهی و کلید جدید صادر کنید: `scripts/setup-ssl-renewal.ps1` را دوباره اجرا کنید (روش DNS-01 که قبلاً استفاده کرده‌اید)؛ `_ssl-post-install.ps1` مسیرها را در `.env` به‌روز می‌کند.
3. فایل‌های قدیمی را از `.ssl\` پاک کنید و دسترسی‌ها را طبق بخش ۳ دوباره بررسی کنید.
4. `nssm restart FarazHonarAttendance` و بررسی ورود از مرورگر (قفل HTTPS معتبر).

### د) دیتابیس یا بک‌آپ لو رفت
- رازی در آن‌ها نیست (توکن/کلید در `.env` است)، ولی **داده‌ی شخصی کارمندان** است. موضوع را به مسئول شرکت اطلاع دهید تا طبق سیاست داخلی تصمیم بگیرند.
- در جداول دیتابیس هیچ توکن، کلید یا رمزی ذخیره نمی‌شود (بررسی‌شده روی ستون‌های همه‌ی جدول‌ها)؛ کدهای یک‌بارمصرف ورود پنل هم فقط در حافظه‌ی پروسه‌اند. آیدی‌های تلگرام، کد پرسنلی و ساعات تردد ذخیره می‌شوند.
- اگر فایل `.env` هم همراهش بود، موارد الف تا ج را انجام دهید.

### ه) رازی در تاریخچه‌ی git رفته
حذف از تاریخچه (`git filter-repo` یا BFG) **جایگزین چرخاندن راز نیست**؛ هر کسی که قبلاً کلون کرده نسخه‌ی قدیمی را دارد. اول راز را بچرخانید، بعد (اختیاری) تاریخچه را پاک کنید.
در بررسی مخزن فعلی، `.env` و `.ssl` و `*.db` در هیچ commit ای ردیابی نشده بودند.

## ۵. چک‌لیست قبل از ارسال/استقرار
- [ ] `npm run secret-scan` ← تمیز
- [ ] `npm test` ← سبز
- [ ] فقط خروجی `npm run package` ارسال می‌شود
- [ ] در سرور production: `NODE_ENV=production`، `ADMIN_SESSION_SECRET` ≥ ۳۲ نویسه‌ی تصادفی، `TELEGRAM_BOT_USERNAME` پر
- [ ] دسترسی `.env` و `.ssl\` با `icacls` بررسی شده

## ۶. محدودیت‌ها (صادقانه)
- اسکنر الگو-محور است؛ هر رازی را پیدا نمی‌کند (مثلاً رمز با فرمت غیرمعمول). مکمل است، نه جایگزین احتیاط.
- `.env` محلی عمداً اسکن نمی‌شود؛ محافظتش با دسترسی فایل و `package-release` است، نه اسکن.
- تعویض توکن/گواهی را سیستم نمی‌تواند خودکار انجام دهد؛ باید صاحب پروژه دستی انجام دهد.
