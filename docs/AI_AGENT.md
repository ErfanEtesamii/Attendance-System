# ایجنت هوش مصنوعی پنل («تحلیلگر هوشمند»)

## راه‌اندازی
دو حالت (در `.env`؛ نمونه‌ی کامل در `.env.example`):

**۱) رایگان/محلی — سازگار با OpenAI (پیشنهادی برای شرایط تحریم)**
```
AI_PROVIDER=openai
AI_BASE_URL=http://localhost:11434/v1   # Ollama روی همین سرور
AI_MODEL=qwen2.5:14b                    # باید tool/function calling داشته باشد
AI_API_KEY=                             # برای Ollama لازم نیست
```
با Ollama هیچ داده‌ای از شرکت بیرون نمی‌رود. سرویس‌های ابری (Gemini، Groq، OpenRouter) هم با همین حالت و آدرس خودشان کار می‌کنند، ولی دسترسی/محدودیت منطقه‌ای و سقف رایگانشان را خودتان باید بررسی کنید.

**۲) Claude**
```
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
```
اگر سرور مستقیم به API دسترسی ندارد، `AI_BASE_URL` را روی relay بگذارید.

سپس سرویس را ری‌استارت کنید. فقط نقش `admin` دکمه‌ی «✦ تحلیلگر هوشمند» را می‌بیند. کیفیت تحلیل و تسلط به فارسی با مدل‌های کوچک محلی پایین‌تر از مدل‌های بزرگ است؛ حتماً با چند کارمند نمونه خروجی را بسنجید.

## معماری
- `src/services/aiAgent/tools.js` — ۱۱ ابزار فقط‌خواندنی روی همان سرویس‌های نمودارها. هر ابزار مجوز و اسکوپ خودش را چک می‌کند؛ ورودی مدل اعتبارسنجی می‌شود؛ کلیدهای مالی حذف می‌شود.
- `src/services/aiAgent/agent.js` — حلقه‌ی tool-use با Messages API (fetch، بدون وابستگی تازه). سقف مراحل `AI_MAX_TOOL_ROUNDS`.
- `src/api/routes/admin/ai.js` — route، محدودیت نرخ (`AI_RATE_LIMIT_PER_MINUTE` به‌ازای هر کاربر) و ممیزی.
- `public-admin/js/ai-assistant.js` — پنجره‌ی چت (رندر امن، بدون innerHTML).

## امنیت و حریم خصوصی
- داده‌ی عملکرد (نام، حضور، تأخیر، تسک) برای تحلیل به سرویس مدل ارسال می‌شود؛ حقوق و نرخ ساعتی ارسال نمی‌شود.
- ایجنت چیزی را تغییر نمی‌دهد. خروجی «تحلیل خودکار» است و تصمیم نهایی با مدیر.
- متن پرسش (نه پاسخ) در `audit_log` با action = `ai_assistant_query` ثبت می‌شود.

## افزودن ابزار تازه
یک آیتم به آرایه‌ی `TOOLS` در `tools.js` اضافه کنید (`name`, `description`, `input_schema`, `run(ctx, input)`) و داخل `run` مجوز لازم را با `need(ctx, '...')` چک کنید.


## ابزارهای ایجنت و داده‌ی در دسترس

فقط‌خواندنی و محدود به نقش پرسنده (ai.assistant = admin):

- عملکرد/تأخیر/نرخ حضور/مرخصی/ساعت ورود/الگوهای رفتاری/بازرسی یک روز (۱۱ ابزار اصلی نمودارها)
- `attendance_log` (تردد و استراحت)، `remote_work`، `tasks_overview`، `leave_requests` (+ مانده‌ی مرخصی)، `disputes`، `overtime_decisions`، `shifts_holidays`، `suspicious_events`، `checkin_permissions`
- `org_overview` (ساختار سازمان)، `panel_settings` (تنظیمات پنل بدون گروه‌های امنیت/زمان‌بندی)، `audit_trail` (فقط admin/hr)، `system_status` (بستن ماه، Jobهای ناموفق، هشدارها)
- `payroll_summary` (حقوق و نرخ ساعتی): فقط با مجوز `payroll.read` (admin) و `AI_ALLOW_PAYROLL` (پیش‌فرض true). هر استفاده با `via: ai_agent` در audit ثبت می‌شود. بقیه‌ی ابزارها هیچ داده‌ی مالی نمی‌خوانند و خروجی‌شان با `stripFinancial` پاک‌سازی می‌شود.

نکته‌ی حریم خصوصی: با سرویس ابری، خروجی ابزارها (و در صورت فعال‌بودن، مبلغ حقوق) به آن سرویس ارسال می‌شود. با Ollama محلی هیچ داده‌ای از شرکت خارج نمی‌شود.

سقف توکن در دقیقه‌ی سرویس‌های رایگان کم است: خروجی هر ابزار ≤ ۹۰۰۰ کاراکتر، تاریخچه‌ی چت ۶ پیام، و روی خطای 429 تا ۳ بار صبر و تکرار انجام می‌شود.
