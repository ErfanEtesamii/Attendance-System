## ۱. پیش از استقرار (روی سیستم توسعه)

```powershell
npm install
npm test
npm run smoke
npm run secret-scan
```

هر سه باید سبز باشند (`secret-scan` کد خروج ۰ = بدون یافته). **تست‌های فاز ۱۲ هنگام نوشتن مستندات اجرا نشده‌اند**؛ اگر چیزی قرمز شد، استقرار نکنید. سپس `npm run package` برای zip تحویل بدون `.env`/`data`/`node_modules`.

## ۲. استقرار روی سرور (PowerShell، Administrator)

> از `data\attendance.db` یک بک‌آپ دستی بگیرید (`npm run migrate` هم پیش از اعمال، بک‌آپ سازگار با WAL می‌گیرد).

```powershell
cd "C:\path\to\Attendance System"
.\deploy\nssm.exe stop FarazHonarAttendance
Copy-Item data\attendance.db "data\backups\pre-phase12-$(Get-Date -Format yyyyMMdd-HHmm).db"
# جایگزینی کد (بدون دست‌زدن به .env و data\ و .ssl\)
npm install
npm run migrate                            # اعمال ۰۲۸ تا ۰۳۲
npm run migrate:status                     # همه باید applied باشند
.\deploy\nssm.exe start FarazHonarAttendance
```

- پنج migration تازه: `028_user_shift_assignments`، `029_user_day_schedules`، `030_paid_breaks`، `031_checkin_permissions`، `032_urgent_tasks` (همه افزایشی و idempotent؛ `028` برای هر کارمندِ دارای شیفت یک ردیف با تاریخ `1970-01-01` می‌سازد تا گذشته عوض نشود).
- `.env` تغییر اجباری ندارد. دو متغیر اختیاری تازه در `.env.example` هست: `CRON_URGENT_TASK_REMINDER` (پیش‌فرض `*/10 * * * *`) و `CRON_TEAM_REVIEW_ENSURE` (پیش‌فرض `10 0 * * *`). اگر آن‌ها را دستی به `.env` سرور اضافه نکنید، پیش‌فرض‌ها کار می‌کنند.
- تنظیم‌های تازه همه خاموش‌اند: `paidBreakCount=0`، `paidBreakMinutes=0`، `lateMonthlyLimit=0`، `lateLimitGateMode=off`. بعد از استقرار، استراحت با حقوق و سقف تأخیر تا وقتی ادمین روشن نکند هیچ اثری ندارند.
- جایگزینی یک‌جای کیبورد قدیمی بات (اختیاری): `node src\scripts\pushPanelButton.js --apply`. بدون آن هم هر کاربر با اولین لمس دکمه‌ی قدیمی کیبورد جدید را می‌گیرد.
- `MINI_APP_URL` باید `https` باشد؛ با `http` دکمه‌های «ثبت تردد/برنامه هفتگی/پنل مدیریت» به‌جای باز شدن، راهنمای ادمین می‌دهند.

### تغییر رفتاری که بلافاصله بعد از استقرار دیده می‌شود
- **منوی بات:** کیبورد پایین فقط «📂 منو» است.
- **سرپرست‌ها:** تسک واجب «بررسی گزارش روز قبل» به‌صورت خودکار در برنامه‌ی هفتگی‌شان می‌آید (نیاز به خاموش‌کردن ندارد ولی خبر دادن به سرپرست‌ها خوب است).
- **ورودی ساعت** در پنل متنی‌ست (نه چرخ ساعت).
- **تسک فوری** و **نمای هفتگی کارمند** فعال‌اند (فقط وقتی کسی استفاده کند اثر دارند).

### فعال‌سازی تدریجی
1. **استراحت با حقوق:** اول روی یک شیفت آزمایشی (`paid_break_count=3`، `paid_break_minutes=15`) و گزارش‌ها را چک کنید؛ بعد سراسری.
2. **سقف تأخیر:** `lateMonthlyLimit=3` و `lateLimitGateMode=soft` برای یک ماه (فقط هشدار و audit)، بعد `enforce`. قبل از `enforce` مطمئن شوید همه‌ی سرپرست‌ها در بات/پنل صف «اجازه‌ی ورود» را می‌بینند.

## ۳. چک‌لیست تست دستی (نسخه‌ی تست، تلگرام واقعی)

به ترتیب. کارمند آزمایشی، یک سرپرست و یک ادمین لازم است.

1. **پاسخ ادمین به اعتراض:** کارمند اعتراض ثبت کند ⇒ ادمین از **بات** «💬 پاسخ و بستن» بزند ⇒ کارمند اعلان تلگرام با لینک مستقیم بگیرد و پاسخ را در گفت‌وگوی «اعتراض‌های من» (Mini App) ببیند.
2. **شیفت ۱۵:۳۰–۲۱:۰۰:** شیفت را به کارمند بدهید (با «از تاریخ») ⇒ ورود ۱۵:۴۰ ⇒ تأخیر ۱۰ دقیقه؛ خروج ۲۰:۳۰ ⇒ زودتر رفتن ۳۰ دقیقه؛ خروج ۲۱:۳۰ ⇒ اضافه‌کاری (طبق تنظیمات اضافه‌کاری). روزهای گذشته عوض نشوند.
3. **استراحت با حقوق:** `paidBreakCount=3`، `paidBreakMinutes=15` ⇒ سه استراحت ۱۵دقیقه‌ای کسر نمی‌شوند (`breakUnpaid=۰`)؛ استراحت چهارم کاملاً کسر می‌شود؛ استراحت ۲۵دقیقه‌ای فقط ۱۰ دقیقه کسر شود؛ ناهار مثل قبل بدون حقوق.
4. **سقف تأخیر:** `lateMonthlyLimit=3`، `lateLimitGateMode=enforce` ⇒ کارمند با ۳ تأخیر قطعی (روزهای قبل) ⇒ ورود دیرِ بعدی ۴۰۹ و کارت «درخواست اجازه‌ی ورود» ⇒ درخواست ⇒ سرپرست از بات/پنل تأیید کند ⇒ ورود موفق، اجازه `used`، ساعت ورود واقعی. ورود به‌موقع هیچ‌وقت مسدود نشود.
5. **override روز:** برای یک روز مشخص ساعت ویژه یا «آف» تعریف کنید ⇒ اثر آن در حضور، تأخیر و تقویم؛ روز داخل ماه بسته ⇒ رد با پیام فارسی؛ سرپرست فقط برای زیردست خودش.
6. **تسک فوری:** سرپرست از پنل یا بات برای کارمند تسک فوری بگذارد (حتی در هفته‌ی شروع‌شده) ⇒ کارمند اعلان بگیرد و برچسب «⚡ فوری» ببیند ⇒ تا پاسخ ندهد خروج (در `dailyReportGateMode=enforce`) مسدود باشد ⇒ کارمند نتواند آن را حذف/ویرایش کند.
7. **نمای هفتگی کارمند:** در پنل ادمین و پنل سرپرست (فقط زیردست مستقیم) «📅 برنامه‌ی هفتگی» ⇒ KPI، شبکه‌ی ۷ روزه، تسک‌ها، فوری‌ها، درصد تکمیل؛ هفته‌ی ماه بسته فقط‌خواندنی.
8. **دورکاری (H1): ⛔ قابل‌اجرا نیست؛ H1 پیاده‌سازی نشده.** بعد از اجرای H1: تعریف ساعت دورکاری برای یک کارمند ⇒ ورود از بیرون شبکه‌ی شرکت فقط در همان روز مجاز و تأخیر بر اساس ساعت دورکاری.
9. **منوی بات:** روی گوشی فقط دکمه‌ی «📂 منو» پایین صفحه باشد؛ با لمس آن بقیه‌ی دکمه‌ها (نقش‌محور) باز شوند و بعد از انتخاب پاک شوند.
10. **بازشدن پنل/Mini App:** بدون زدن دکمه‌ی آبی چپ، «ثبت تردد»، «برنامه هفتگی» و «پنل» از منو باز شوند و کاربر وارد شده باشد (ثبت ورود انجام شود).
11. **کیبورد ساعت:** در فرم اصلاح رکورد (پنل و بات) روی گوشی با یک لمس کیبورد عددی بالا بیاید و ساعت تایپی (مثل `1530` یا ارقام فارسی) ثبت شود.
12. **تسک واجب سرپرست:** سرپرست در برنامه‌ی هفتگی‌اش تسک «🔒 واجب: بررسی گزارش روز قبل زیردست‌ها» را بدون افزودن دستی ببیند (حتی بدون ثبت برنامه)، «۳ از ۴ گزارش مشاهده شد» به‌روز شود و با مشاهده‌ی همه‌ی گزارش‌ها خودکار done شود؛ حذف/ویرایش ممکن نباشد.

مرور UI: عرض ۳۲۰px، RTL، تم روشن/تیره و خوانشگر برای کارت اجازه‌ی ورود، هشدار استراحت، بنر فوری و نمای هفتگی.

## ۴. بازگشت (Rollback)
`.\deploy\nssm.exe stop FarazHonarAttendance` ← بازگردانی کد قبلی و بک‌آپ `pre-phase12-*.db` (طبق `BACKUP_RESTORE.md`) ← `.\deploy\nssm.exe start FarazHonarAttendance`. migrationهای ۰۲۸ تا ۰۳۲ فقط جدول/ستون اضافه می‌کنند و کد فاز ۱۱ با آن‌ها کار می‌کند، ولی بازگردانی بک‌آپ تمیزترین مسیر است. توجه: تعریف‌های شیفت/override/اجازه/تسک فوریِ ثبت‌شده بعد از استقرار با بازگردانی بک‌آپ از بین می‌روند.
